# CTOS Pipeline Audit — 2026-11-11

## Verdict

The baseline implementation is a strong **CTOS 2026 on EventScribe** extraction and verification system—not yet a general-purpose arbitrary-URL extractor. Its offline transformation stages are evidence-linked and thoroughly tested; its platform boundary, release gating, packaging, synthetic test isolation, and repository governance have been hardened so the codebase can be shared safely with zero raw or embargoed CTOS data in Git.

This release (`0.2.0`) provides an installable CLI (`conference-pipeline`), validated conference/embargo configuration, capture attribution and `robots.txt` fail-closed guards, isolated run directories with `SHA-256` manifests, hard QA/reviewer release gates, synthetic CI fixtures, and strict data-governance documentation. It intentionally does not claim support for arbitrary conference website layouts.

## What Was Reviewed

| Area | Finding |
|---|---|
| Capture | An EventScribe-specific direct collector plus a controlled browser fallback collect public listings and detail cards with pacing, `429` backoff, and `robots.txt` verification. |
| Parse | The detail-card parser (`Method D`) extracts presentations, sessions, people, sponsors, events, abstracts, affiliations, disclosures, and schedule metadata deterministically. |
| Enrichment | Curated dictionaries and INN grammar rules assign disease, drug, drug-target, modality, biomarker-polarity, company, and trial tags with exact character-offset evidence quotes. |
| Readouts | Candidate scoring ranks clinical abstracts and deterministic verification checks manually curated readouts; it does not autonomously invent unverified clinical outcomes. |
| Assemble / Export | Aggregates, Draft 2020-12 JSON Schema validation, JSON, `.json.gz`, analyst CSV, run report, and delta tracking are implemented. |
| Tests & Fixtures | Real CTOS HTML and gold files were excluded from Git and replaced with synthetic fixtures under `tests/fixtures_synthetic/`, preserving full parser, tagger, readout, QA, export, and release-gate coverage. |

## Baseline Output Audited (Aggregate Summary Only)

The evaluated CTOS 2026 candidate dataset contains **772** presentations (**645** posters, **117** oral talks, **2** lectures, **8** other), **645** abstracts, **20** sessions, **3,956** people, **11** sponsors, **3,844** evidence-linked tags, and **59** clinical readouts (772 CSV rows).

Although the candidate document reports `schemaValid: true`, the release gate properly identifies **five unresolved release blockers**:

| Gate Check | Failures / Count |
|---|---:|
| `readout_ci_contains_estimate` | 1 |
| `readout_count_denominator` | 1 |
| `readout_arm_n_sum` | 1 |
| Readouts pending human review (`needs_review`) | 2 |

Because of these five blockers—and because abstract content is governed by CTOS embargo rules—the candidate dataset is **not publicly releasable** and remains restricted to private internal triage.

## Key Risks and Disposition

| Priority | Risk | Disposition |
|---|---|---|
| P0 | A schema-valid export could be mistaken for a releasable dataset despite failed numeric QA and pending review. | **Fixed:** `conference-pipeline run` exits non-zero unless all QA checks and human-review gates clear; `--allow-qa-failures` is explicit for triage only. |
| P0 | Raw bundles, real HTML fixtures, gold labels, and abstracts may be embargoed or confidential. | **Fixed:** `.gitignore` excludes raw/stage/gold/real-fixture/report artefacts; tests run on synthetic fixtures in `tests/fixtures_synthetic/`; governance rules documented in `docs/data-governance.md`. |
| P1 | Parser constants and capture endpoints are CTOS/EventScribe specific, which could mislead users if framed as arbitrary-URL support. | **Fixed:** Config validation fails closed outside `eventscribe-ctos-v1`; `README.md` and `docs/adapter-guide.md` state the adapter requirement explicitly. |
| P1 | Raw bundles are excluded from Git, so external clones cannot regenerate CTOS outputs from Git alone. | **Expected by governance:** Handled operationally via private raw-bundle storage and `SHA-256` hashes recorded in `run-manifest.json`. |
| P1 | Direct capture previously risked running with a placeholder contact or an unconfirmed `robots.txt` state. | **Fixed:** Live HTTP capture requires a valid contact email and fails closed when `robots.txt` cannot be established. |
| P2 | Packaging, CI, licence, and deployment documentation needed standardization. | **Fixed:** Validated `pyproject.toml`, Python 3.11–3.13 GitHub Actions CI, `sdist`/wheel build verification, and deployment/governance checklists. |

## Recommended Next Implementation Increment

Introduce a formal `Adapter` protocol class and isolate EventScribe capture/parsing under a dedicated adapter namespace before onboarding the second conference platform (see [Adapter Guide](adapter-guide.md)). Keep every adapter independent, synthetic-fixture tested, rate-limited, terms-reviewed, and fail-closed on DOM drift.
